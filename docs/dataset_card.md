# Capstone distillation data: short chain of thought from Qwen3.5-9B

Teacher data for turning [wongwian-micro-instruct](https://huggingface.co/wongwian-org/wongwian-micro-instruct)
(272M parameters, Thai, 2,048-token context) into a small reasoning model.

- **Prompts:** from No Robots, HelpSteer2, UltraFeedback and LogiQA 2.0 (logic puzzles with four options).
- **Teacher:** Qwen3.5-9B answered each prompt with thinking on. Its thinking was then rewritten into a few
  short reasoning steps.
- **Judge:** Gemma 4 31B scored every sample.
- **Language:** English, plus Thai sets (`final_th`, `final_th_closed`, …). Their questions are new ones, translated
  from English first (the original is in `input_en`), so Qwen wrote the Thai reasoning and answer itself.

**This dataset is private, internal and unreviewed.** Ask before sharing anything outside the team (see Licenses).
Generated by the project's `distill push`; edit `docs/dataset_card.md` in the project repo, not this page.

## Final rows: the training data

| field | meaning |
|---|---|
| `input`, `rationale`, `answer` | **The training sample:** the prompt, the reasoning steps (separated by a blank line), then the answer. |
| `id`, `sample_idx`, `source_dataset` | Which prompt, and which of its samples. Keep `source_dataset`: No Robots and LogiQA rows are non-commercial. |
| `closed`, `gold` | Whether the prompt has a known short answer, and that answer (closed prompts only). |
| `complexity`, `max_steps`, `n_steps` | Reasoning complexity 1–5 (the curriculum order), the step limit it set, and the steps actually written. |
| `student_tokens` | Lengths in the **student's** tokenizer. `total` includes 32 chat-template tokens and stays ≤ 2,048. |
| `selection` | How the row was chosen: `method`, the judge's `score` (1–9) and `expected_score`, `n_candidates`, `n_passing`. |
| `teacher` | How Qwen made it: model, prompt versions, sampling settings, seed. `max_tokens` is the teacher's limit, not the student's. `thinking_tokens` counts the raw thinking, which is only in the `samples` subset. |
| `lang`, `input_en`, `translation` | Thai rows only: `th`, the English question `input` was translated from, and the translation's model, judge meaning score (1–5), fluency and embedding similarity. |

Rows are ordered from easy to hard: complexity 1 first, shuffled within each level.

## How a row is made

1. **Rate:** each prompt gets a reasoning-complexity level from 1 to 5 (the DeReason prompt, arXiv:2603.11193).
2. **Generate:** Qwen writes 2 samples for level-1 prompts and 4 for the rest, with thinking on.
3. **Compress:** the thinking is rewritten into at most 4, 5, 6, 8 or 10 steps for levels 1 to 5.
4. **Filter:** drops wrong-language, repetitive, unfinished and over-length samples. Every row must fit the student's
   2,048-token context.
5. **Judge:** Gemma scores each sample from 1 to 9. For closed prompts, rules check the answer first: UltraFeedback's
   known short answers, or LogiQA's option letter.
6. **Select:** an open prompt keeps its best sample if it scores at least 7. A closed prompt keeps up to 3 distinct
   correct samples.

A Thai row starts one step earlier: a question the English run never used is translated into Thai. Rules, the judge
(is the meaning kept, is it fluent, does the task only make sense in English?) and embedding similarity check the
translation, and only translations that pass are distilled. Their files are in `data/full_th/`, the translations in
`data/translate/`.

## Files

Paths mirror the project repo. `hf download <!-- repo --> --repo-type dataset --local-dir .` puts them back in
place, and the pipeline resumes from them. For each set, in `data/full/`:

| file | contents |
|---|---|
| `*_raw.jsonl` | Generations before compression |
| `*_B.jsonl` | The same samples plus the compressed `rationale` (the `samples` subset) |
| `*.kept.jsonl`, `*.kept.rejected.jsonl` | Samples that passed the filter, and the ones it dropped |
| `*.kept.judge.jsonl` | Judge scores for the kept samples |
| `*.final.jsonl` | The training rows |
| `*.runs.jsonl`, `*.errors.jsonl` | Run summaries, and failed calls (retried on the next run) |

`data/prepared/*.complexity.jsonl` holds the complexity ratings.
